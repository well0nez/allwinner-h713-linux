# userspace/ - what runs on the board

| Directory | What | State |
|---|---|---|
| [`h713-tv/`](h713-tv/README.md) | **The HDMI input as a service.** C, one process: shows the capture ring on the KMS plane (or the warp's frames), and h713-osd's page without a signal on signal loss; sends the preset and the gamma curve at the start; control channel `h713-tv ctl …` (controls, presets, aspect fit, picture on/off, a raw RPC). Runs as a template unit, one instance per capture device (`h713-tv@videoN`, started by udev, `BindsTo`; the number varies with probe order). | in service (08.09.2026) |
| [`h713-pq/`](h713-pq/README.md) | **The PQ calculator.** Python, reads the stock PQ data (`pq_picturemode.ini`, `tvpq.db`, …) and computes RPC arguments and DE2 gamma LUTs. Writes nothing to the device; `gamma-standard.bin` in `h713-tv/` comes from here. | finished, a tool |
| [`h713-focus/`](h713-focus/README.md) | **Driving the focus motor by hand.** One Python script, without dependencies. `status` / `up` / `down` / `flush` / `unlatch`; reads the range guard before and after every movement, has a hard upper bound per run, and never writes `motor_ctrl_no_limit`. Replaces the first `focus` shell script. | finished (12.09.2026) |
| [`h713-cam/`](h713-cam/README.md) | **The internal camera.** One Python script, without dependencies. `probe` / `controls` / `get` / `set` / `grab` (PNG); finds the node by its name instead of guessing `/dev/video2`; writes the exposure back once before the picture (the camera delivers black otherwise). Out of `analyse/beamer-cam/`. | in service (12.09.2026): node found by name, controls and `grab` verified on the device |
| [`h713-autofocus/`](../docs/tools/h713-autofocus.md) | **The autofocus, rebuilt from the vendor's own.** One Python script, without dependencies. Chessboard on `/dev/fb0`, YUYV frames from the internal camera, the vendor's cubed-gradient metric and its five-state search; per-board step table, `run --dry-run DIR` replays recorded frames and `measure --metric-only FRAME` times the metric. The metric is also a C helper, `h713-afmetric` (cross-built, optional). | climbs and sharpens on the device; turns round at a range edge and found a peak on the bench (23.09.2026); a run against a wall ended sharp at the same position as the run before (02.10.2026, `doku/134` A4) - one evening |
| [`h713-warp/`](../docs/tools/h713-warp.md) | **The keystone and the zoom on the GPU.** C, one daemon: warps the capture ring into NV12 on the Mali-G31, projection modes and soft edge; `h713-warp ctl ...` | in the image since `v0.95-beta` |
| [`h713-keystone/`](../docs/tools/h713-keystone.md) | **The automatic keystone.** One Python script with the vendor's geometry in `model/`: the accelerometer's tilt into the eight corner values, once after a move | in the image since `v0.95-beta` |
| [`h713-panel/`](../docs/tools/h713-panel.md) | **The settings as a web page**, port 8080, one password since 05.10.2026; every button is a command of the tools above | in the image since `v0.95-beta` |
| [`h713-features/`](../docs/tools/h713-features.md) | **Which optional hardware this board has** - camera, accelerometer, focus motor - against `/etc/h713/features`; a one-shot unit at boot | in the image since `v0.96-beta` |
| `h713-remote-pair/` | **The stock Bluetooth remote.** One Python script over `bluetoothctl`: `pair`, `reconnect`, `status`, `forget`, and `watch`, which the unit runs ([details](../docs/subsystems/wifi.md#bluetooth)) | in the image since `v0.96-beta` |
| [`h713-keys/`](h713-keys/README.md) | **The stock remote's keys.** One Python script, a daemon: volume and mute through `h713-tv`, the focus through `h713-focus`, an input key (still to choose) switches between HDMI and the console; Bluetooth and IR (kernel 0252-0254), never a keyboard. One line per action to the overlay daemon `h713-osd`, when it runs; Home opens the launcher, which starts the modes (Kodi, desktop, browser, settings) | IR measured on the HY310 (11.10.2026, all 14 keys), both remotes on both boards (22./23.10.2026); in the image since `v0.97-beta` |
| [`h713-osd/`](h713-osd/README.md) | **The overlays over the picture.** C daemon: volume, mute (with a badge that stays), focus (red at the end), input, as a pill at the bottom; pre-distorted with the warp's matrix over a keystone; shown by `h713-tv` on the primary plane. Fed by `h713-keys`; `h713-osd ctl ...` by hand | on the HY310 since 11.10.2026 (7-15 ms a refresh); in the image since `v0.97-beta`, with the launcher, the pages and the page without a signal |
| [`libh713geom/`](libh713geom/README.md) | **The keystone geometry.** C source library: the eight corner values, the vendor's matrix, projection modes, zoom, `/etc/h713/warp.conf`, and the way back from the panel to the source. Taken out of `h713-warp` (bit-identical binary) for `h713-osd` | in `h713-warp` since its start; the way back new (11.10.2026), host-tested |
| [`libh713osd/`](libh713osd/README.md) | **The overlay pictures.** A C library, libc and libm only: volume, mute, focus (red at the end of the travel), input as ARGB - white lines in a translucent pill (or bare with a soft shadow); signed distance fields, no font file; `osd-mockup` renders every case on the host. For `h713-osd`, which draws the launcher and the pages with it too | in the image since `v0.97-beta`; the pill at the bottom (11.10.2026) |
| `h713-gpu-probe/` | **A GPU check.** C: `info` and a `render` run with a CRC per frame, the measurement behind the Mali's row in STATUS.md | a bench tool, not in the image |

Building and installing: `doku/50-befehle.md`, the operation section. The old stock rebuilds `hy310-hdmird`
and `hy310-pqd` (C++ daemons with an RPC layer of their own) are gone from the tree; their knowledge sits in the
kernel drivers (`doku/77` §3).
