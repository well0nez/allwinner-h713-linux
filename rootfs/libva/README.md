# `rootfs/libva/` - the VA-API driver for the hardware decoders

`build-libva.sh` cross-builds one module, `usr/local/lib/dri/v4l2_request_drv_video.so` (about 150 KiB, links libc only), the
VA-API driver that lets stock ffmpeg, mpv, GStreamer `va*dec` and Kodi decode on the SoC: H.264, HEVC, MPEG-2, VP8, VP9 on the
video engine (cedrus) and AV1 on its own core (hantro; that core is switched off in the kernel at present, patch `0310`, so
libva offers no AV1 profile). The decoders themselves are kernel drivers; this module is the part
that sits between libva and their V4L2 stateless interface.

| | |
|---|---|
| base | `libva-v4l2_request` v1.2 + one README commit, `cac6ece0e23ac1f944dd3af266680aff0c3184df`, <https://xff.cz/git/libva-v4l2_request/> (Ondrej Jirman, GPL-3.0-or-later). Fetched at build time and pinned by that commit; nothing of it is in this repository |
| patches | `patches/`, in the order of `patches/series`. `0001`-`0009` are Christopher Stenger's, made on the same base; each keeps his `From:` and carries an `Origin:` line naming his file, and apart from that line they are his files byte for byte. `0010` on are this project's (GPL-3.0-or-later like the code they change): `0010` gives a surface exported before its first decode the layout of the context that will decode into it (GStreamer `vaav1dec` into GL was green: the AV1 core appends its motion vectors to every buffer), `0011` offers NV12 only for HEVC Main10 when the decoder writes 8-bit samples (cedrus; FFmpeg picked P010 and every download failed), `0012` adds `V4L2_REQUEST_SCALE=panel` (decode-time scaling to the size of the panel, only for pictures larger than the panel; not run on the device yet), `0013` makes `vaDeriveImage` refuse a surface the scaler has shrunk (the mapped image would not match the surface), and `0014` backs a bare 10-bit surface with NV12 when no decoder writes P010 or PL10 (cedrus alone): its export failed, so Kodi's interop probe said "deepColor no" and played HEVC Main10 in software. `0015` keeps a decode context alive while another thread is inside a surface call: vaSyncSurface, vaQuerySurfaceStatus and vaDestroySurfaces against vaDestroyContext on a resolution change could use the freed context. `0016` hands cedrus the entry points of an HEVC slice with several tiles (without them cedrus programs the slice's first tile only - read in its code, not seen on the device; the header parsing is checked on the host against FFmpeg's, on streams with several tiles in one slice, but the change has not run on the device yet), `0017` takes the VP8 quantiser deltas from a segment that was not clamped (segment 0's clamped base gave the other segments a wrong DC or AC index). They fix what 1.2 as released gets wrong on this SoC (AV1 crashes, a resolution change crashes, GStreamer's dma-buf export shows green) and add the H713 specifics: the AV1 core's 10 bit layout (`PL10`), the decode-time scaler (`V4L2_REQUEST_SCALE`, `V4L2_REQUEST_CROP`), an opt-in linear P010 export for GL (`V4L2_REQUEST_LSB10_LINEAR`). Each patch's own message says what and why |
| licence | GPL-3.0-or-later for the module and for `patches/`. `build-libva.sh` and the meson cross file `rootfs/mesa/cross-aarch64.ini.in` are GPL-2.0-or-later, so GPL-3 can take them in as part of the Corresponding Source. The tarball carries `COPYING`, a `SOURCE` note and, under `source/`, megi's tree at the pinned commit (`.tar.xz`), the patches with their `series`, the build script and the cross file, all under `usr/local/share/doc/libva-v4l2-request/` |
| build | `rootfs/libva/build-libva.sh` in the build container, against the arm64 sysroot of `release/build-all.sh` step 6 (`libva-dev` is in its package list). Writes `libva-v4l2-request-1.2.tar` to `mainline/build/out/` (or `$OUT`). Same inputs built in the same directory give the same bytes. Built in another directory, the module differs in its 20-byte build ID (`.note.gnu.build-id`: the linker hashes the debug info, which holds the build paths, before `--strip` removes it) and in nothing else, so compare two builds without that section (`objcopy --remove-section=.note.gnu.build-id`); the `SOURCE` note differs with the commit |
| use | `rootfs/build-rootfs.sh --profile media` or `--profile desktop` lays the tarball in (`--libva`), together with `rootfs/overlay-va/`: `/etc/environment.d/h713-media.conf` names the driver (`LIBVA_DRIVER_NAME=v4l2_request`, `LIBVA_DRIVERS_PATH=/usr/local/lib/dri`) and `/usr/local/share/h713/systemd/h713-media-env.conf` hands the same file to a system unit (`EnvironmentFile=`). The base image carries neither |

The kernel side (the cedrus changes and VP9, the AV1 core and `PL10`) is in `mainline/patches/kernel/`; without it the module finds no decoder
and libva reports no profiles.
